## Actual Java model adapter
- `sources/org/workflowsim/planning/StagedScheduleBatchEvaluator.java` directly creates and evaluates the existing full Java `StageInAwareScheduleEvaluator` and `ReadyQueueScheduleEvaluator` on the supplied **list of full physical Task→VM genotypes**. It computes exactly one OLD decode per genotype, OLD-only shared planned reference, greedy OLD shortlist T, lazily invokes READY EXACTLY T times and greedily selects K. Returns detached Task→VM mapping copies, screened indices, selected indices, actual Java `System.nanoTime` old/ready/total batch timing and exact OLD/READY decode-call counts. **This is an isolated candidate batch adapter, not a modified evolutionary optimizer.**
- Actual model wiring and safety unit `tests/org/workflowsim/planning/StagedScheduleBatchEvaluatorTest.java` uses 4 original Tasks with dependencies and two real `CondorVM`s to validate K1/T2, K2/T3, K4/T4, deterministic repeated selection, exactly T READY calls and no mutation of original assignment maps.

## Essential scientific boundaries
1. **Do not claim algorithm superiority**: the only true WorkflowSim HV scoring so far uses a fixed 16-placement historical candidate universe, not actual newly evolved FLA population fronts. Candidate selection is NOT evolutionary fitness integration, and the default FLA v12, seeded NSGA-II and WorkflowSim FIFO dispatch are unchanged.
2. The greedy method avoids exact combinatorial explosion but does not guarantee exact maximum predicted HV or optimal Pareto quality; this cohort was small, heavily skewed to many ties and a few CyberShake gains. Need new fixed candidate distributions, unseen DAG families, multiple seeds and real cost data to test generalization.
3. The Java microbenchmark's synthetic DAG decoder work proxy is NOT end-to-end speed; an actual comparable Java FLA/NSGA optimizer must count every old and ready decode, measure search and shortlist selection wall time, compare equal computed evaluation budgets and K16 real simulator HV/IGD+ on fixed reference points.
4. A staged evaluation selector that works identically for BOTH FLA and seeded NSGA-II is engineering model/computation strategy, **not** an FLA-specific novel search operator by itself. Published rule-learning and multiobjective workflow models exist; novelty review and ablation still required for Q1 publication.
5. Original master untouched; all new Java classes/tests/workflows and reports confined to `fla-baseline`. The source model's default remains the historic StageIn/FLA configuration, and the opt-in staged batch adapter must be explicitly invoked.

**Research decision: scalable batch implementation is ready for a FAIR controlled real-population, true-WorkflowSim FLA vs NSGA-II replay selection gate. That next gate, rather than more retrospective 16-point tests, is required before a journal claim.**
