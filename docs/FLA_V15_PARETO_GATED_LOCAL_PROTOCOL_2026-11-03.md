# v15 Pareto-gated local-survivor trial — registered development protocol

v15 is NOT an original FLA equation and is default OFF. It is a target-evaluation-budget-neutral correction to the v14 local paired offspring design. In each pair the normal FLA child and its one-gene neighbor each receive EXACTLY one charged stage-in-aware PLANNING fitness evaluation. If the already-evaluated neighbor is STRICTLY Pareto-dominated by its own normal child in (planned makespan, planned rental cost), replace that neighbor's next-generation candidate slot with the existing normal child (no extra true evaluations); otherwise retain the neighbor. Independently, the normal archiveConsider(trial) mechanism and passive full candidate recorder still observe every evaluated neighbor. This is an offspring **survivor gate**, not deletion or fabrication of a fitness evaluation. The gate makes duplicated normal children possible and thus can reduce effective population diversity, which is a scientific risk.

Six-arm comparison: unchanged v12-hvbandit, ungated v14-randompair, ungated v14-timelinepair, v15-randomgate, v15-timelinegate, equally cost-seeded NSGA-II. Each has exactly 3030 planning target objective evaluations and 16 independently simulated WorkflowSim candidate replays using original Pareto-cover, same first two deterministic cost-seed genotypes; each paired mode has exactly 1400 local trial evaluations. Compare v15 timeline vs v14 timeline (gate effect), v15 random vs v14 random (gate effect independent of timeline), v15 timeline vs v15 random (incremental timeline effect), and v15 timeline vs v12 and NSGA-II (true optimizer comparisons). Do not conflate these effects.

Locked development case: Montage_25, CyberShake_30, seeds 161/162, default/staggered VM speed profiles (8 blocks), original predeclared primary simulator HV reference =1.5× the coordinatewise PLANNED K16 maxima across six arms/two seeds for each DAG/speed +1; 3× sensitivity. Fail rather than retroactively widen an invalid reference. Report every negative result. This is an exploratory development study on historically used DAG families, NOT an independent test of generalizable algorithm superiority. No parameter retuning on these labels followed by treating them as untouched validation.
