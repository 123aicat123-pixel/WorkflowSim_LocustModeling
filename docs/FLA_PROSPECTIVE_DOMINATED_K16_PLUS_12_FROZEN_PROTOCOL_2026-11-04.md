# Prospective K16 plus K12 planning-dominated candidate replay: selected-front bias control (frozen 2026-11-04)

**This protocol was written BEFORE any source results in its new 4-case run.** Its hypotheses were motivated by the already existing retrospective 1024-replay analysis; previous 6320 selected-K pair labels are DEVELOPMENT evidence, NOT prospective holdout. The new DAG families have been used in earlier studies, so these are new optimizer seeds/cases, not unseen-family testing.

## Hypothesis
K16 planner Pareto-cover sampling includes mostly planned-nondominated genotypes. That selection suppresses predicted-dominance pairs and can make the 205/6320 observed only-new-real-dominance mismatches misleading as a universal model property. Replaying strictly planning-dominated/unselected genotypes under a second independent, deterministic protocol should expose cases where a predicted dominance is *lost or reversed* after actual WorkflowSim execution and clarify whether K16 true HV misses valuable rejected solutions.

## Registered original source implementation
- New **explicitly opt-in** `-Ddagfla.allowSeparateKPlusScreeningDiagnostic=true` modifies only a historical exclusivity guard in `FLAResearchExperiment`. It allows a normal K=16 prospective simulator replay and a **separate** `screeningAuditPerAlgorithm=12` after the normal source front is frozen; original defaults still reject combined replay if explicit opt-in is OFF.
- Original identical StageInAware objective for FLA v12 and cost-seeded NSGA-II; runtime priority FIFO. `dagfla.screeningAuditIncludeTies=true`, `dagfla.screeningAuditAllVisited=false`; no online label-driven candidate selection.
- Source `runScreeningAudit` already existed: choose up to 12 unique visited genotypes not selected by primary K16 and dominated under at least one planned K16 point or tied; first 6 are nearest to planned front, second 6 uniformly sampled by frozen `seed XOR algorithm-name hash` from the remaining pool. Candidate generation and stratum assignments use ONLY PLANNED evaluations, **NOT actual simulator values**. Actual true results are measured only after selection.
- If fewer than 12 eligible unselected candidates exist, fail the research gate rather than alter DAG/seed rules. Never count these 12 extra actual replays as primary K16 normal optimization budget; the extra replays are post-search diagnostics, so original algorithm Pareto/HV result remains unchanged.

## Frozen 4-block true WorkflowSim experiment
- Workflows `Montage_100`, `CyberShake_50`, search seeds 951,952, `staggered` VM speed and original prices, static FIFO schedule. Two original solver arms per block: `DAG-Pareto-FLA[v12-hvbandit]`, `NSGA-II[costseed]`.
- Population 30, 100 generations, **3030 counted genotype fitness evaluations per solver**, 16 original K-selected true WorkflowSim calls **plus 12 separately budgeted diagnostic true calls**; 4 blocks × 2 solvers ×28 = **224 actual simulator replays**, of which 96 are diagnostic samples. Fair deterministic same two initial cost seeds per original solver pair.
- Exact original per-arm `research_summary.csv`, `research_replays.csv`, `research_screening_summary.csv` and `research_screening_samples.csv` archived with original SHA. Fail on missing genotypes, duplicate physical maps between K16 and extra K12, wrong source metadata, nonfinite actual metrics, or unequal counts.
- Primary experiment question: **What fraction of originally planned-dominated/tied extra K12 candidates become truly nondominated against the original K16 real candidates?** Count each independently sampled extra candidate only within its source K16 set. Report actual real Pareto-HV gain of K16+K12 under a **shared reference for all 56 true points in each DAG/seed across both algorithms**, not a run-local reference comparison or fabricated full-front optimum. An additional 3.0× sensitivity reference.
- Pairwise rank: in each solver's 28 true candidates, calculate exact Pareto dominance classification mismatch, specifically predicted planned dominance **lost**, **reversed**, and **new** true dominance; separately report the original planned K16-only 120 pairs and the 12×16 cross-stratum pairs. Compare direction error with original selected-K retrospective but NEVER treat same-DAG pair counts as independent trial replicates.
- Report metadata: archived sampling strata near-planned-front/uniform remainder, time to run additional simulator samples (post-search, not optimization search_ms), exact true makespan and cost, original mapping and priority, duplicate/tied selection, and negative cases.
- No algorithm deployment from observed labels. This is **diagnostic experimental evaluation** to decide whether a new rank-aware model should be designed, not a new FLA search method. `master` untouched; original configurations unchanged.

## Scientific limitations
At most two DAX instances and two seeds, historically familiar families, strongly correlated candidate pairs within K16+K12 and algorithm-selected search populations. No statistical significance, new-family generalization, or SCI Q1 superiority claim. Even if a dominated planned candidate is truly valuable, selecting it after seeing simulator labels would be an invalid oracle for future optimization.
