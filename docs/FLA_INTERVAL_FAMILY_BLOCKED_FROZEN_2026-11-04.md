# Freeze: family-blocked error-envelope interval certification — 2026-11-04

**Research question:** The earlier fixed-epsilon [read-only 96 actual WorkflowSim interval gate 41789732628](https://github.com/123aicat123-pixel/WorkflowSim_LocustModeling/actions/runs/41789732628) showed READY: epsilon10% covered 96/96 source mappings with 115/720 certified strictly-better-both-coordinate comparisons, zero wrong certified classifications. But epsilon10% was prescribed, NOT calibrated, and all 3 DAX families were familiar development families. The next audit must test whether a purely preheld-out family maximum-error envelope can safely generalize at all, before any optimizer integration.

## Frozen deterministic source & split
Use ONLY six original true WorkflowSim artifacts in original [Actions 41695356307](https://github.com/123aicat123-pixel/WorkflowSim_LocustModeling/actions/runs/41695356307). Check raw task-VM mappings, source SHA, six DAG/VM blocks with `fla_algorithm_independent_same_mapping_rank_audit.load`, no new simulation or optimizer. Three DAX instances CyberShake_30, Epigenomics_46, Montage_50, each with default/staggered speed, 16 same Task→VM genotypes per speed. For each target whole DAX family, use the OTHER TWO whole families (64 points) for error envelope. The held-out family (32 points) must not enter envelope selection.

## Frozen bound and certification
For each model OLD and READY, derive **two coordinate-specific** worst-case relative error widths from the 64 training points:
`epsilon_m = max_training |actual_M/planned_M − 1|`, `epsilon_c = max_training |actual_C/planned_C − 1|`. Use a fixed outward numerical buffer of `1e-9` fraction for floating-point boundary handling. Never clip widths to a favorable value and never tune based on held-out true labels. If a width is greater or equal to 1, report it but do not use a negative lower bound; fail closed if an invalid interval. It is not a statistical distribution-free coverage theorem.
For each held-out speed×16 block, construct `[planned_i*(1−eps_i),planned_i*(1+eps_i)]`, certify A dominates B only if upper_A < lower_B in BOTH dimensions, otherwise abstain. Score 120 pairs per block, 240 pairs per target family, 720 total held-out pair decisions for each model across 3 held-out families. Use actual labels ONLY for scoring after certification. Track false confident direction, abstentions, dominance recall, pointwise joint true coverage, worst held-out error exceeding training envelope, retained candidate count, lost true non-dominated source mapping, actual normalized 1.5× and 3.0× HV fraction vs all16 held-out actual mapping outcomes.
Report all 6×2 model/speed fold results and 3×2 model/family envelope training summaries, along with explicit false-certain pair rows.

## Negative-result guardrails
This is a deterministic **leave-one-family-out developer stress test** over only THREE familiar families with correlations between two VM speeds. It is not an independent new-family external holdout, not an upper confidence bound, not a statistically guaranteed uncertainty interval, not a novel Pareto algorithm and not new CloudSim data. If certifying nearly zero pairs or missing important held-out objective errors, that is a gate failure for useful safe evolutionary pruning; do not shrink bounds to make the algorithm look useful. No changes to master, original FLA/NSGA evaluation defaults, runtime FIFO or user data.
