# Frozen staged-decoder low-K screening study — 2026-11-04

**Preoutcome status:** this protocol is committed BEFORE executing the new 2-stage screening script. The earlier exact K-only 96-source experiment is completed at Actions 41768405985; this new evaluation reuses exactly the SAME immutable old/ready predicted values and true simulator results. It is therefore **a retrospective developer study, not a new true simulator experiment or independent holdout**.

## Hypothesis
A cheap StageIn-aware insertion decoder (OLD) can identify a small shortlist that is valuable to re-evaluate with the potentially more expensive event-driven ready-queue model (READY). The expensive estimate should be computed only for preselected genotypes. This might preserve the tiny true K2/K4 HV gains of full READY while using fewer READY evaluations; it can also fail if OLD rejects a point that READY would recognize as promising. No claim of faster wall clock is made without Java timing measurements.

## Immutable source and integrity
Exact 96 original actual WorkflowSim outcomes from source [41695356307](https://github.com/123aicat123-pixel/WorkflowSim_LocustModeling/actions/runs/41695356307), verified by `fla_algorithm_independent_same_mapping_rank_audit.load`, six blocks (CyberShake_30, Epigenomics_46, Montage_50 × default/staggered) ×16 distinct pre-registered algorithm-independent VM genotypes; same original VM assignments and real outcomes for OLD and READY. No optimizer evaluation, new simulator calls, model fitting, hyperparameter tuning, or label-guided selection permitted.

## Locked pipeline
1. For EVERY 16-point source block, define one **OLD-only** planned HV reference as (1.5×max OLD planned Makespan +1e-6, 1.5×max OLD planned Cost +1e-6), based solely on the cheap OLD outputs. No READY estimates or simulator outcomes may be used to define the screening reference. The same OLD-only reference is reused for all model-only K selections, hybrid and random screen controls.
2. For prospective true-replay quotas **K=2 and K=4**, register high-fidelity screening budgets **T=4 and T=8** READY model calls per 16 candidate genotypes. Thus four (K,T) combinations ×6 blocks, with T≥K. All 16 cheap OLD estimates are always computed.
3. `OLD-only`: select exact predicted normalized-HV-maximizing size-K subset across 16 OLD predicted points. `FULL-READY`: select exact best-K among all16 READY predicted points under the SAME OLD-only reference (full 16 READY calls; no OLD shortcut). `STAGED-T`: select exact predicted normalized-HV-maximizing OLD size-T subset FIRST. Replace OLD estimates by READY estimates on those T indices ONLY. All unselected estimates remain OLD, including potential false-negative genotypes. Select exact predicted normalized-HV-maximizing size-K subset of these 16 hybrid estimates. `RANDOM-T` budget-matched control: identical hybrid evaluator except the T indices are a deterministic pseudo-random sample of the original 16, from SHA256 seed derived solely from strings `RANDOM_20261104|DAX|speed|K|T|replicate`. Use 12 immutable replicates `rep=0..11` for a descriptive random-selection distribution. Both strategies use exactly 16 OLD and T READY estimates, whereas full READY uses 16 READY estimates. A `16 OLD +T READY` operation count is **NOT equal to** T READY model compute time.
4. All K choices maximize the same normalized two-objective predicted HV by exact subset enumeration. Tie tolerance 1e-12 absolute normalized HV, lexicographic order of the 16 original source policy indices; never access real labels during selection. The `FULL-READY` selector and `OLD-only` use the OLD-only ref (may differ from the older source 41768405985 model-common reference).
5. After recording chosen indexes, score actual WorkflowSim HV against the SAME within-block true reference for all strategies: 1.5× (plus 1e-6) max actual Makespan and Cost of all16 genotypes. Also use a 3.0× actual ref sensitivity; no score under incompatible references.
6. For each fixed group/K/T record full old/full ready/staged/random actual HV recovery fraction of actual full16 K-candidate universe; number of identical FULL-READY vs STAGED selected mappings; regret in percentage points vs FULL-READY (can be negative if model misranks); actual truth-based K optimal only for post-hoc upper bound, never to choose stage T. Report positives, ties, losses, exact underlying selection IDs and all random replicate outcomes. Explicitly report count of READY calls and estimated work via OLD/READY call counts **without** claiming a wall-clock speedup.
7. Materiality screen 0.1 percentage points of *actual fixed-16 HV recovery*, not 0.1% objective difference; report both unfiltered and screened effects. Negative conclusion if STAGED does not retain FULL-READY advantage more efficiently than random, if true gain is negligible or if it cannot reduce READY calls while retaining same actual HV.

## Scientific limits
Only 3 previously researched DAG families and 2 correlated VM profiles, with unusually extreme fixed mapping policies. This is **not** full FLA population behavior, not a prospective holdout, not a new joint model and not a publication-level statistical claim. Future work, if supported, needs reproducible Java per-decoder timing, a genuinely unchanged baseline, an identical multi-objective FLA/NSGA-II scheduling budget, several independent DAG-family holdouts and full true K16+ HV. Do not promote default objective or change master. Retain full data including adverse cases.
