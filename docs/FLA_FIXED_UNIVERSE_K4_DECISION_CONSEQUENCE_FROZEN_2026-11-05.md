# Prospective fixed-mapping Pareto decision-consequence validation (2026-11-05)

**Locked BEFORE obtaining any true WorkflowSim outcome for these new task-size/VM blocks.** This is a planner/simulator decision fidelity experiment, NOT a new FLA optimizer, SCI novelty or unseen-family holdout.

## Independent causal question
Earlier plan-selected K16 audits were structurally biased toward planned Pareto points; subsequent random K16 work found planned strict dominance errors. Yet those often had negligible impact on actual HV. This experiment directly asks **how much actual K4 Pareto quality do OLD vs READY planning-only choices lose relative to an actual-truth restricted 16-mapping oracle?** All 16 candidate TaskID→VMID assignments are fixed WITHOUT any optimizer or simulator-informed sampling.

## Immutable source and frozen independent mapping universe
- Reuse existing untouched `FLAAlgorithmIndependentMappingUniverse.java` and exactly its **16 predefined fixed placement strategies**, including all-vm extremes, round-robin and stride, VM-block, skewed, prime-step and hashed mappings. These policies are already source-checked and must not be added/removed/tuned after seeing results.
- Eight new **instance-size × VM profile** blocks relative to previous same-mapping 96: `Inspiral_100`, `Sipht_100`, `Epigenomics_24`, `CyberShake_100` × `default`,`staggered`. All four DAG families have been studied elsewhere; these are new exact source size/profile combinations, **NOT brand-new family-level holdouts**. Static FIFO WorkflowSim runtime, original VM cost/bandwidth, simulator seed 1501, 16 unique original physical placement assignments per block.
- Each program invocation returns each original physical mapping's OLD StageInAware and READY event-queue plans and the identical true WorkflowSim original Makespan/Cost from one replay, along with task-level true start/finish error; the program validates all TaskID/VMID identities and 16 distinct mapping genotypes. No FLA search and no extra optimization evaluations. Eight jobs ×16 real physical replays = **128 original actual simulator records**, with original source commit fixed per job and all input CSV artifacts preserved.
- Frozen planned-only **K4 decision policy**: for each planner separately choose FOUR mappings greedily by normalized predicted 2-objective HV gain, tie lexicographic mapping_policy; reference for a planner = (1.5×max predicted Makespan+1e-6,1.5×max predicted Cost+1e-6) over all 16 maps for its own block; when greedy marginal HV ties, choose lowest predicted normalized sum of makespan/max and cost/max, then frozen mapping-policy lexicographic. ZERO true simulation outputs used in any K4 selection. K4 cardinality exactly four.
- Controls: deterministic FIRST FOUR of the original frozen policies (no training, same K4), OLD predicted K4, READY predicted K4, and **true-oracle exhaustive C(16,4)=1,820 fixed-four subset choice**, which is strictly a hindsight upper ceiling, not an implementable algorithm.
- Evaluation computes true normalized Makespan–Cost HV under ONE shared actual reference for all methods in each DAG/profile block: (1.5×coordinate-wise maximum true outcomes among all 16 mappings +1e-6); repeat with factor 3.0 sensitivity. Primary **realized HV regret = hindsight-oracle K4 true HV − predicted K4 actual HV** and comparisons OLD-vs-READY-vs-fixed blind K4. No per-method self-references for true performance.
- Secondary: rank fidelity on ALL 120 mapping pairs within each block, including genuinely planned-dominated pairs; count false strict planned dominances, reverse dominances, new true dominances, ND Jaccard, material (0.1% true objective margin) false dominances, makespan/cost order errors, and mean absolute relative error. The 120 comparisons within each block are NOT 120 independent cases.
- Fail closed on 8 input blocks / 128 physical mapping count / all policy names / exact source SHA / physical TaskID 1..N mapping / positive finite objectives / fixed K4 cardinality / shared actual reference/true-oracle dominates all controls; test all negative results.
- No claiming READY superiority or model-fidelity novelty unless robust across original DAG/VM blocks, and no publication-level inference on just eight known-family blocks. No total CPU parity claim; both models run on same mapping but READY has extra event computation cost.

## Follow-up gate
If the predicted planning model selects the same K4 every time as blind fixed control, any good regret score is NOT evidence of model benefit. If both planners produce serious but inconsistent regret, the result supports a paper focused on uncertainty/evaluation fidelity rather than a new FLA operator. If an estimator improves regret, new independent DAG family/VM regime, 20+ blocked seeds and measured actual compute overhead remain necessary before publication claims.
