# Staged OLD→READY decoder: model-only real-HV screening and Java evaluator compute-cost gate (2026-11-04)

**Current verdict: a promising finite-candidate efficiency mechanism, NOT a validated end-to-end FLA innovation.** The frozen high-fidelity screening experiment retained full-READY true fixed-16 HV in 6/6 groups for K2/T4 and K4/T8; K4/T4 missed a CyberShake case by 0.0699021 percentage points. Actual Java evaluator timing on synthetic DAGs shows compute savings depend on DAG size/structure: T4 saves 13.7%–59.5% of measured-decoder-work proxy in the nine tested cases, but T8 is SLOWER than full READY for some 30/100-task workloads.

## Frozen Java time gate: actual evaluator implementations, NOT theoretical call counts
- Timing protocol frozen before execution `docs/FLA_STAGED_DECODER_JAVA_COST_FROZEN_PROTOCOL_2026-11-04.md`, commit `30ec99a`.
- `tests/org/workflowsim/planning/StagedDecoderJavaCostBenchmark.java` directly invokes the EXISTING actual Java `StageInAwareScheduleEvaluator` and `ReadyQueueScheduleEvaluator` with `Task` and `CondorVM` instances. Uses synthetic predeclared graph structures chain/forked/independent, tasks N=30/100/200 and 16 VMs, **no DAX file data-transfer**. 4×16 warmup passes per model, 6 ×128-call rounds per model and synthetic shape, alternating model order. A volatile result protects against JVM dead code elimination; all real timings preserved.
- [Java real class microbenchmark 41775597558](https://github.com/123aicat123-pixel/WorkflowSim_LocustModeling/actions/runs/41775597558) **SUCCESS**, all **108 raw per-model timing rounds** archived, complete Java clean build and old decoder regressions PASS. `scripts/fla_staged_decoder_java_cost_report.py` independently checked counts and median ns/candidate. STAGED timing PROXY =16×median OLD time +T×median READY time, FULL READY =16×median READY time, excluding selector and any optimizer execution.
- For N=30/100, STAGED T4 was faster than FULL READY by 13.7%–33.3% in all six synthetic cases; T8 was **slower by 0.6%–11.3%** in four of those six cases (faster only for independent task DAGs). At N=200, T4 proxy savings **53.0%–59.5%**, T8 **28.0%–34.5%** across three synthetic DAG structures. The READY/OLD median per-candidate cost ratio varied from 1.63× to 6.45×, so fewer READY calls does not guarantee overall savings.

## What can and cannot be claimed
1. We now have a **reproducible, predeclared finite-genotype proof-of-concept** that cheap OLD shortlist plus selective expensive READY re-evaluation can retain FULL READY exact low-K candidate choices on several correlated known-instance blocks, while a budgeted synthetic Java timing proxy suggests real compute benefit in some task regimes. The K4/T4 false-negative is essential.
2. **Not end-to-end FLA**: exact `choose(16,T)` and `choose(16,K)` predicted-HV enumeration is not scalable to normal 30–100+ individual populations and selection time was excluded. STAGED uses **16 OLD +T READY** decode calls whereas FULL READY uses **16 READY**. Simulated-genotype evaluation budgets and real CPUTIME are not equal just because READY calls are reduced. On full realistic DAX and optimizer search, benefits could disappear.
3. The original 96 actual simulator labels were available from prior experiments, but staging decisions themselves use ONLY model forecasts. This retrospective test cannot support an unseen-family generalization or a claim of robust new optimizer superiority.
4. Direct next engineering gate: implement a scalable incremental 2D HV greedy shortlist and selection routine (rather than exhaustive combinations), with Pareto-gate admissibility and deterministic ties. FIRST validate it against the 16-case exact benchmark and report any greedy quality losses. Then integrate as an explicit separately selectable evaluation budget mode in both FLA and seeded NSGA-II, measure genuine full wall-clock and high-accuracy calls on real DAX before any publication claim. Because this is a shared decoder strategy, it is not FLA-specific novelty alone.
5. No automatic promotion of OLD+READY staged selection as `FLA v20`; existing FLA v12, seeded NSGA-II, FIFO CloudSim runtime, and `master` remain untouched. All experimental results live only on `fla-baseline`.

**Decision: continued research justified specifically for cost-aware screen-and-refine mechanics; Q1 novelty and solver gain remain unproven.**
