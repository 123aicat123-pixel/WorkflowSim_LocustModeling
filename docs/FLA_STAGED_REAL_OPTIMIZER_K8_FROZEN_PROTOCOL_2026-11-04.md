# Frozen first real-optimizer candidate replay staged vs FULL READY gate — 2026-11-04

**Pre-registered before running the algorithm-level study. No retrospective changing the algorithms or picking favorable runs.** Previous 96-point fixed mapping staged-greedy success is NOT an actual FLA population result; here we compare once-visited real *optimizer* genotype pools.

## Design
- DAX instances: `CyberShake_50`, `Sipht_60`, `Epigenomics_100` (all historically used families, so these are development tests, not publication holdout); independent fixed optimizer seeds `801`, `802`, standard 16 VMs, default speed and cost, original FIFO runtime and StageIn-aware search objective.
- Use `FLAResearchExperiment v12-nsga-ready-pair`: exactly 2 algorithms per block `DAG-Pareto-FLA[v12-hvbandit]` and `NSGA-II[costseed]`; same seeded initial two genotypes. Population=30, generations=100, expected 3030 counted original genotype search objectives each. No search trajectory changes between replay-selector policies.
- Candidate universe for each solver is `budgetedPlannedCoverage(allVisited,32)`: the same deterministic 32 unique visited original genotypes chosen using ONLY original planned objective values and not actual simulator truth; canonical mapping order preserved. All three replay selectors must compare the SAME 32 source genotype IDs. Strict source SHA/genotype fingerprints and first-two-seed identities must match.
- Three prospective modes, independent CI jobs:
  1. `old-greedy`: 32 StageIn OLD post-search predictions, choose K=8 via deterministic marginal-HV greedy; no READY calls.
  2. `ready-greedy`: 32 OLD predictions to build the exact SAME OLD-only HV reference and 32 READY TaskID predictions, greedy choose K=8 from READY; 32 READY calls, 32 OLD.
  3. `staged-greedy`: 32 OLD predictions, greedy OLD select T=8 shortlist, EXACT 8 READY callback calls, mixed OLD+READY greedy choose K=8. All modes use common OLD-only planned HV reference and identical greedy tie tolerance. These are screening policies, NOT replacing the 3030 counted fitness evaluations from FLA or NSGA-II.
- All 8 selected physical maps are replayed in actual WorkflowSim with original FIFO runtime and unchanged Task ID→VM mapping (the normal source exact-assignment assertions). No true simulator labels enter selection; simulator truth is used ONLY after selecting all K genotypes.
- For 3 DAX × 2 seeds × 3 modes × 2 solvers × K8 = **288 true WorkflowSim replays**. There are 18 original paired optimizer jobs. Full 32 candidate post-search evaluation operations for all modes, T8 high-fidelity for staged only. Record measured actual OLD and READY Java nanoseconds, full selection time and total complete search/replay wall time, and strict call counts per solver.
- Source Task/VM references are captured ONLY under opt-in `dagfla.stagedReplayContext=true` and bound to each solver's completed planning run. No modification to default optimizer objective or runtime.
- Analysis uses one shared 1.5× and 3.0× true reference from all 6 solver×mode K8 actual replay sets within each workflow/seed block. Compare paired true normalized HV staged-vs-ready (primary fidelity), staged-vs-old (secondary), positive and negative cases and per-solver wall-clock/operation overhead; independent parent initial seeds, search budget and canonical all-visited genotype fingerprints MUST match between modes (no oracle).
- Source objective evals=3030 are **not the same** as extra postsearch old/ready decodes: report both. `ready-greedy` has 32 OLD reference decodes +32 READY decodes, `staged-greedy` 32 OLD+8 READY, `old-greedy` 32 OLD only. Primary quality per actual K8 replay, and secondary compute time per selector. No claim that saved READY calls imply end-to-end speedup.
- No promotion based on a single favorable DAX/seed, no tuning K/T/candidate pool after seeing results; at least 6 blocks here across three previously studied workflow families, still insufficient for SCI Q1 significance/generalization. No changes to `master` or default FIFO behavior.
