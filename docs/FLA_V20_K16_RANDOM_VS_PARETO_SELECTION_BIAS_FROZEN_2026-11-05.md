# V20 independent replay-selection bias: prospective random K16 vs planned Pareto-cover K16 (2026-11-05)

**Frozen BEFORE any new randomly selected true WorkflowSim simulations. This is a model-fidelity/measurement study, NOT a new optimizer and NOT an SCI performance claim.**

## Testable hypothesis and design
- Published K16 results for source run `41969565802` chose physical assignments via **PLANNED** Pareto-cover. Hence its 16-point sample is selected for likely planned non-dominance, which can mask the false planned-dominance and reversal rate. A previously independently archived rank study of 1,024 selected points documented the same selection bias (and should NOT be rebranded as novel).
- Use exactly the same four original v20 experimental arms and **same** DAG, seed, population and generations as that source: CyberShake_50/Sipht_60/Epigenomics_100 × seed 951/952 × original FLA-v12, v20 random-novelty, v20 DAG-novelty and seeded NSGA-II, all with 3,030 target evaluations. Keep original source implementation and VM profile, FIFO simulation unchanged.
- New study changes **ONLY the prospective replay selector** to `-Ddagfla.budgetReplayPolicy=random`, replicate=0, fixed canonical TaskID->VMID ordered physical genotype universe. Choose K=16 independent of planned objectives AND real labels, after optimization. Six source jobs × four arms × K16 = **384 NEW actual WorkflowSim replays**. If any case has non-matching exact ordered distinct-visited search history SHA-256 versus the original planned K16, fail closed.
- Original planned-selected K16 source artifacts are **immutable** from run 41969565802, 6/6 success, so this is a **paired re-selection of already inspected optimization histories**. It is not a new independent optimizer-seed or workflow-family validation, and original policy test outputs have been seen. No learning, tuning, or source changes based on actual test labels.
- Both original and randomized selectors must share the same source Java code semantics, original 3,030 objective visits, 4 solver arms, deterministic low-cost seed assignments and K16 true simulator budget. Original source SHA and new source SHA may differ due to diagnostic-only files, but identical ordered candidate-history SHA plus unchanged algorithm Java source must be audited; no assumptions from same seed alone.
- Assess **within each arm and selector** of 16 true mappings: planned pairwise dominates, true pairwise dominates, false planned dominance (a predicted dominated or dominating orientation that is false in truth), full reverse dominance, planned incomparable→true dominance, planned dominance→true incomparable, makespan discordant fraction, planned-vs-true non-dominated set Jaccard, plan-makespan absolute error. Do not interpret 120 within-arm pairs as independent observations.
- Primary selection-bias diagnostic: the paired count of planned-dominance pairs and their false-orientation rate under RANDOM versus original PLANNED Pareto selection. If the planned-Pareto sample has zero planned-dominance pairs, the *zero false dominance* observation there is non-informative, not a perfect predictive model.
- Secondary: pooled common 1.5× reference normalized **actual K16 HV** per (DAG, seed) across all 8 solver×policy arms, reference sensitivity 3×, exact TaskID->VMID overlap (zero or nonzero), winner/tie/loss for planned-covered versus random. This is a control for selection, NOT demonstration of a better FLA optimizer. Analyze within known DAG/seed blocks; do not claim new unseen-family or time-matched superiority.
- Methodological uncertainty: even RANDOM K16 is a tiny sample of ~3,030 proposals and only one replicate; it may contain mostly dominated genotypes and is not a distribution-free estimate of true-wide Pareto error without a justified sampling design. No universal ranking guarantees.
- Reject any result if source arrays, source fingerprints, actual K16 replay counts, VM config, SHA provenance, true label positivity, or fixed analysis code do not match. Preserve all positive AND negative cases.
- No edits to `master`, v20 search defaults or historical simulation outputs.
