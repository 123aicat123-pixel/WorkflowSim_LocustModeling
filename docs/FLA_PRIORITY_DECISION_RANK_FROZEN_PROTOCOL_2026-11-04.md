# Freeze: policy decision-rank fidelity and regret audit (2026-11-04)

## Motivation
Earlier source-verified FLA v19 and matched restarts failed to establish an optimization advantage; a reliable predictor of makespan values is NOT necessarily a reliable decision ranker. Prior new-instance data were generated at full WorkflowSim fidelity and archived in Action 41682109356, independent audit 41682284043. This gate performs **zero new optimizer and zero new simulator runs**. It must NOT treat known development cases as fresh holdout.

## Fixed source and scope
Only immutable original 8 artifacts of 41682109356: two DAX instances Inspiral_30, Epigenomics_100 (previously known families), two VM speed profiles default/staggered, two unoptimized deterministic Task->VM assignments round_robin/stride7, and three fixed policy modes FIFO/SHORTEST/UPWARD. Exactly 8 blocks × 3 policies = 24 real source points. All policies saw the SAME Task-to-VM map per block. The ranker uses the already archived priority-aware predictor, NEVER real simulator outcomes as model inputs.

## Primary metrics, fixed before computing results
1. Pairwise comparisons among the 3 policies within each block, 3 pairs × 8 blocks = 24 pairs. Mark a difference **material** if absolute actual Makespan gap divided by the lesser actual Makespan exceeds 0.001 (0.1%). Report number of material pairs and fraction with the correct predicted *direction*. Ties within threshold are not correct/incorrect classification, and do not enter accuracy denominator. Report every sign error and all near-ties separately.
2. Policy decision regret: use only predicted Makespan to select a policy (tie tolerance 1e-9 relative then deterministic preference FIFO < SHORTEST < UPWARD). Evaluate the chosen policy by actual WorkflowSim Makespan; compute regret relative to the *post hoc* lowest actual makespan **for evaluation only**, not for selection; percentage regret = (actual_chosen/actual_best−1)×100. Also report FIFO regret and policy choice distributions across 8 blocks. This is a miniature 3-policy decision problem with fixed assignment, NOT a joint mapping+priority optimizer.
3. Search model must NOT be judged solely by mean MAPE: a same-sign error on all large deterioration cases can make the model look good while predicting a globally invalid optimum. Record worst-case regret, median/mean regret and count of regret exceeding 0.1%. On near-ties, avoid overclaiming tiny effects.
4. No task mapping search, FLA code modification, policy tuning, additional source jobs, or new simulator labels. Each case belongs to only two DAG instances and related mapping/speed conditions, so neither 24 independent samples nor formal Q1 scientific significance.
5. Cost is a secondary tradeoff: include original actual Cost and source-predicted priority model Cost when available. The current new-instance CSV does not expose policy-cost in the derived summary, so do NOT invent cost predictions or assert a fully Pareto-aware ranker. Future Pareto-pair ranking needs archived raw policy CSVs or a separate frozen full cost-aware evaluation.
6. Do not promote the priority model into any default search algorithm solely on this result, even if all 24 pairs are ordered correctly. Existing CyberShake SJF sign failure must remain a negative control in the final discussion.

## Testable provenance
Audit should fail closed unless all 8 source artifact names are uniquely present, every block has exactly FIFO, SHORTEST, UPWARD, source workflow/profile/mapping identity matches, all actual and predicted Makespans >0 and finite, all source percentage changes recompute correctly from FIFO, and the source post-forecast prediction is exactly the one measured in its corresponding complete original job. A single all-case CSV, pairwise CSV, regret CSV, and complete Markdown report must be archived.
