# Prospective diagnostic: visited Pareto-objective coverage versus replay K16 (2026-11-05)

**Status: protocol frozen BEFORE the new source-run outcomes.** This is a failure-mode diagnostic to select a future research direction, not a new optimizer and not a claim of FLA superiority.

## Motivation
The previous exact observed K12+4 hindsight replay oracle (original WorkflowSim 41975729241, exact-audit 41981439412) found only +0.000051718 mean possible FLA real-HV improvement in the observed 12 replacement alternatives. Yet the original optimizers visit ~3000 distinct candidate mappings per run. The observed-tail ceiling does NOT establish what is possible among the thousands of unreplayed mappings. v12 already rewards source-planned archive HV and v20 maximized genotype-Hamming spread without robust true-HV gains. Before designing another search mutation, distinguish objective-space **candidate-generation/coverage failure** from fixed-K16 replay-selection saturation.

## Predeclared experiment: passive full-visited objective export

- Add a strictly opt-in `-Ddagfla.exportVisitedObjectiveSpace=true` export to `FLAResearchExperiment`, executed **before any real WorkflowSim replay**. Write EVERY ordered distinct evaluated TaskID->VMID map and exact roundtrip planned makespan/cost to `research_full_visited_objectives.csv`. No extra planner, READY, optimizer or simulator calls; no change to RNG, search ranking, selection or objectives. Check all simulated labels are null before export.
- Exact reproducibility: cross-verify every exported row against `research_visited_fingerprints.csv` using the original Java ordered SHA-256 format `canonicalMapping|Double.toHexString(bits M)|Double.toHexString(bits C)\n` (the code actually emits `Long.toHexString(Double.doubleToLongBits(x))`, reproduced byte-for-byte in audit). Enforce 3030 source fitness visits for each arm and `exported_rows=distinct_observed`.
- Development-only cases: `Montage_50`, `Sipht_60`; seeds **981, 982**; both original unchanged `DAG-Pareto-FLA[v12-hvbandit]` and `NSGA-II[costseed]`, population 30 and 100 generations, default VM profile, original static FIFO; fixed planned-only `pareto-cover` K=16 actual WorkflowSim replay per solver. Four original source jobs and **128 planned actual simulator replays**, plus 2×~3000 passive planned-objective rows per job.
- No retrospective source-run selection or tailoring. Planned reference within (workflow,seed): common `1.5× coordinate-wise maximum of all source planned evaluated points + 1e-6` over BOTH solvers; 3× sensitivity. Compute exact (i) planned HV from all distinct visited genotypes (nondominated front), (ii) planned HV from the 16 selected replay maps, (iii) ratio selected/full, (iv) number of distinct planned ND points, (v) selected planned front size, (vi) objective-space occupancy of 10 equal-width planned-makespan bins across each solver's full planned nondominated front, (vii) exact non-dominated source map overlap with K16 selection. This is *planned* model geometry, not truth for un-replayed assignments.
- Separately audit actual K16 simulator HV with a shared actual 1.5× max ref per (workflow,seed), but DO NOT compare to planned full-visited HV numerically as if the objectives/references were equal.
- A 2-run opt-in exporter ON/OFF smoke with identical seed and no changed genotype search or K2 simulator results will be used to detect instrumentation interference. A test failure rejects claims about the full export.
- Report all workflows/seeds and all negative/puzzling cases; per-VM costs and runtime preserved. These two familiar workflow families and two seeds are an **engineering and diagnostic pilot only**, not new family evidence, no statistics.
- If planned K16 already captures essentially all full visited planned HV, then additional *planned-front post-selection* tuning is unlikely to improve predicted HV; still cannot conclude true-unseen HV ceiling. If the gap is materially large, investigate why Pareto-cover misses source points **before** changing search.
