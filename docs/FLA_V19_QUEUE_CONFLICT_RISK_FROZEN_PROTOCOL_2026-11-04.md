# FLA v19 bounded queue-conflict Pareto-risk relocation: frozen first true-simulator gate (2026-11-04)

**Status when preregistered: method source and unit checks implemented, but NO v19 full optimizer/real WorkflowSim outcome has yet been observed. This is an explicitly exploratory scientific falsification, not a validated new paper algorithm.**

## Mechanism (code frozen before first real run)
- Optional FLA-only `CONFIG_QUEUE_RISK_RELOCATION=false`, exposed as `v19-queue-risk` in `DAGParetoFLAPlanningAlgorithm`; the original v12, v18, NSGA-II and all default constructors are unaffected.
- After an original FLA candidate genotype is created, with a locked **0.35 trigger chance** (same chance as exploratory v18), v19 forecasts the already-proposed genotype under **fixed original Task-ID FIFO-ready semantics**, using only DAG, task execution, VM model and stage-in. It locates the potentially conflict-sensitive task maximizing `(predicted scheduled start − max parent finish) × normalized DAG upward importance`, among tasks with at least two allowed VMs. No queue wait => no relocation. This is a targeted mechanism rather than just maximal disagreement (v18).
- From original genotype it constructs at most TWO alternate single-task VM assignments, one based on low service time + local VM workload and one based on local workload-priced service. It forecasts at most two alternatives with the frozen ready estimator (≤3 internal forecasts per activated proposal). It compares predicted makespan and cost without reading any actual future simulator output.
- Group 1 (latency): permit only predicted Makespan-improving moves with at most **1% predicted Cost deterioration**. Group 2 (cost): permit only predicted Cost-improving moves with at most **1% predicted Makespan deterioration**. Score relative improvement −0.25× relative deterioration, accept only strictly positive score. Otherwise preserve the original proposed FLA genotype. Deterministic tie-breaking by task and VM index.
- The final genotype receives exactly ONE countable original StageInAware target-fitness call, same as FLA-v12/v18; the extra ready-model forecasts are **separate uncounted internal model calls** but their count and entire real search_ms are tracked. Do NOT claim computational fairness merely from equal 3030 FLA objective calls. No CloudSim label leakage, no training.
- The existing 4-task regression and new `QueueConflictRiskRelocationTest` derive 22s FIFO -> 21s predicted critical conflict move for latency-focused group, reject cost-neutral fake improvement in cost-focused group, ensure deterministic bounded forecasts and no VM-choice fabrication. This is only a hand oracle, NOT proof on real WorkflowSim.

## Frozen experimental design (no tuning after outcomes)
- 2 DAG instances **Inspiral_100**, **Sipht_100**, known workflow families, 2 independent optimizer seeds **901**, **902**, 16 fixed CloudSim VMs, `staggered` speed regime, same cost model.
- For EACH of 4 (DAG,seed) blocks, four solver arms in the same original `FLAResearchExperiment` source code mode `v19-queue-risk-four-arm`:
  1. **FLA-v12** original, target StageInAware, normal v12 Pareto-HV phase selection;
  2. **FLA-v18** maximal disagreement single-task relocation at same 0.35 trigger probability; negative prior benchmark, same original target fitness;
  3. **FLA-v19** new bounded ready-queue critical waiting/1% risk FLA-specific proposal, same target fitness;
  4. **NSGA-II[costseed]** same cost-seeded fair baseline, unchanged objective & population encoding.
- Each arm uses **population 30**, **100 generations**, exactly **3030 counted genotype target evaluations** and **16 prospective actual WorkflowSim K16 Pareto-cover replays**. Total expected 4 blocks × 4 arms × K16 = **256 actual WorkflowSim replay calls**, 48,480 target objective evaluations. No post-hoc filtering of failing cases. All three FLA arms and NSGA share identical first two cost seeds.
- Primary endpoint: independent normalized **actual WorkflowSim K16** 2-objective HV using ONE shared 1.5× real maximum reference across four solver arms in EACH DAX/seed block (plus 3.0× sensitivity). Compare v19−v12 primarily, v19−v18 mechanistic secondary, v19−seeded NSGA-II parity, and K16 actual non-dom count / minima.
